## 改动 2（字表收敛）：第一版字表把实词一起滤掉了

这条按你的要求留着，包括它是我的错报、你的修复。

### 上一轮发生了什么

改动 3 的第一版 `CJK_FUNCTION_CHARS` 里有 `有`、`不`、`要`、`得`。它们是高频字，看着像虚字，实际不是：

| 问句里的词 | 被切成的 bigram | 第一版字表的后果 |
|---|---|---|
| 所**有**项目 | `所有` / `有项` | 两个都丢（`有` 在表里） |
| 不**要**构建步骤 | `不要` / `要构` | 丢（`要` 在表里） |
| **不**用 sqlite | `不用` | 丢（`不` 在表里） |

而 `所有` 正是 e1「我是不是定过**所有**项目都要零依赖」在问的东西。于是 e1 从第 1 掉到第 3：

| 轮次 | #1 | #2 | #3 | 期望卡 |
|---|---|---|---|---|
| 第三轮（宽字表） | c-20260912-0030 **5.367** | c-20261020-0012 4.899 | c-20260520-0003 **4.808** | 第 3 名 |
| 本轮（收敛后） | c-20260520-0003 **7.272** | c-20260912-0030 5.358 | c-20261020-0012 4.883 | **第 1 名** |

**这是这条规则真正的成本**：它不是「噪声 vs 实词」的干净二分，`有` / `不` / `要` / `得` 既出现在虚词里
（`我有`、`了没`），也出现在实词里（`所有`、`不用`、`所有 DSH 插件`）。
按字做判断就必然在这一类字上犯错，只能选偏向哪一边。

### 收敛后的实测

字表从 39 字减到 36 字（拿掉 `有` `不` `得`，保留 `要`——它在实际出现的 bigram 里都是情态：`都要` / `要不要` / `要零`）。
当前实际的 tokenize 结果：

| 输入 | 现在切出 | 判断 |
|---|---|---|
| `所有` | `所有` | **实词，保住了**（就是 e1 恢复的原因） |
| `有项` | `有项` | 实词（`所有项目` 的另一半），保住 |
| `不用` | `不用` | 实词，保住 |
| `都要` | `（空）` | 噪声，靠 `都` 丢掉 |
| `要不要` | `（空）` | 噪声，靠 `要` 丢掉 |
| `几个` | `（空）` | 噪声，丢掉 |
| `有记` | `有记` | **噪声，回来了**（`有` 不再是功能字） |
| `到底` | `到底` | 噪声，一直在（`到` `底` 都不在表里） |
| `部署` / `零依赖` | `部署` / `零依 依赖` | 实词，保住 |

**代价是明确的：噪声覆盖从 10/10 退回 9/10**（`有记` 又进索引），换来 `所有` / `有项` / `不用` 不被误杀。
这条规则不可能两头都赢，所以我把它写成「按字分类的规则有固有取舍」，
而不是「改动 3 已经完美」。上一轮那句「不含表内字的噪声照样留着」现在要更准确地说：
**含表内字的噪声也不再全丢，因为表变小了。**

## 弱点 8（本轮新加）：「还留着吗」这类现状提问被读成历史

| 名次 | 卡 | 得分 | 状态 |
|---|---|---|---|
| #1 | c-20260530-0027 监控从 Zabbix 换到 Uptime Kuma | **7.191** | superseded |
| #2 | c-20260706-0028 监控换成 Prometheus + Grafana，Uptime Kuma 只留外部拨测 | **7.159** | active |

问句是「监控**之前**那套 Kuma **还留着吗**」。这句话问的是**现在还在不在**，
`之前` 在这里是定语（「之前那套」），不是时间状语。正则看到 `之前` 就当成历史，于是：
老卡从 0.15 放行到 1.0，**以 0.032 之差把正确答案压到第 2**。
0.032 的错答比漏检严重得多——漏检时用户看到 0.05 的兜底，知道没找到；
这里用户看到的是一个**语气确凿的错误答案**。

这不是 `之前` 一个词的毛病，是**二值意图判断的结构性代价**：

- `之前`、`当时`、`原来` 在中文里既能做时间状语（「之前怎么弄的」）也能做定语（「之前那套」）；
- `那套`、`还留着`、`还在用` 是强现状信号，正则完全不看；
- 更根本的是：**「问过去还是问现在」几乎从来不是二值的**。「以前那套现在还留着吗」同时问了两个时间点。

上一轮我预言过这个形状（「一个这样的副词就能把作废卡放大 6.67 倍，这两条之所以没翻只是运气」）。
`原来` 那条救回来了，`之前` 这条翻了——**同一枚硬币，只是换了个面。**

修的方向（没动，等你定）：

- 加**现状信号否决**：问句里出现 `还` / `还在` / `还有` / `现在` / `目前` 时，历史意图不成立，
  或退化成「旧卡不加权、但允许出现」；
- 或者不做二值判断，把整条 supersede 链一起返回、链内按时序排列，让读者自己看两版——
  这也更符合 c-20261005-0011 里写的那条设计原则（「旧方案还能查到，只是压在新方案下面」）。

## 改进优先级

1. **二值意图判断换成连续先验 + 现状信号否决**（弱点 7 + 8）：`还` / `还在` / `还有` / `现在` / `目前` 出现时
   历史意图不成立；`之前` / `当时` 这类两可词不该单独决定方向。或者干脆不做判断，
   把整条 supersede 链一起返回、按时序排。这是唯一一处「错答」级别的缺陷，优先级高于其他所有项。
2. **稀有短词的 idf 上限**（弱点 6）：给 df = 1 的 token 封顶，或要求至少两个 token 命中才算有效命中。
   同时压住 0011 元卡对 t2 / t4 / 两条历史变体的干扰，也顺带缓解「评论区的字体」那种判据灰区。
3. **答案充分性判据**（替代 negative 的 0.5 线）：要求问句的话题实体在命中卡里出现，
   才能把「话题命中但没答案」与「完全无关却高分」分开。
4. **历史问句的两段式处理**（弱点 7 里那 4 条 0.050 兜底）：时间词只用于意图判断、不参与匹配，
   剩下的内容词再走向量/词面匹配，而不是在同一套 token 里解决。
5. **抬高扩展分**（弱点 3）：`0.25` 提到 `0.5` 以上，或给 `via: linked:` 留固定保底名额。
6. **实体命中加权**（弱点 4、5）：entities 里的 token 权重从 1 提到 2。
7. **recency 下限 0.55 抬到 0.7**，或只在分数接近时当 tie-break。
